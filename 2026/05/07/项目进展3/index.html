作业批改系统开发日志 — 游客提交模式改造与Bug修复

发表于2026-05-07|更新于2026-05-07|项目总结Java后端
|总字数:1.2k|阅读时长:4分钟|浏览量:

TL;DR

今天把作业提交从「必须注册登录」改成了「游客模式（文件名解析）」，同时修了一堆连环 bug，包括 JSON 解析、数据库约束、双重拦截、重复提交等。本文记录踩坑过程和修复思路。

背景

作业批改系统原先是老师端内部使用的，学生需要注册登录后才能提交作业。需求改成：学生通过文件名直接上传作业，无需注册登录。

文件名格式：姓名_班级_作业名称.扩展名

问题 1：JWT 过滤器双重拦截

现象

SecurityConfig 已经放行了 /api/homework/**，但前端访问时仍然返回 401。

排查

应用有两个认证层级：

  1. SecurityConfig — Spring Security 配置，已通过 .requestMatchers("/api/homework/**").permitAll() 放行
  2. JwtAuthenticationFilter — 自定义过滤器，在 Security 过滤链之前执行

两层都需要配置放行规则。

问题 3：knowledgePoints 未设置 status 默认值

现象

OpenClaw 返回的 JSON 中 knowledgePoints 数组使用了 status 字段（值为 "掌握"、"薄弱" 等），但代码中 saveKnowledgePoints 没有处理这些值，导致批量插入时该字段为 null。

解决

在 KnowledgeDTO 中确认字段映射正确（JSON 中有 status 字段），代码直接使用 JSON 中的值。

问题 5：前端的重复提交

现象

用户在页面上点击了一次提交后觉得没反应，又点了一次，数据库出现两条相同记录：一条有分数，一条为 null（因为第一次成功，第二次的 knowledge 插入异常走了 catch 分支）。

排查

前端提交按钮没有绑定 :disabled="uploading"，用户可以在请求未完成时再次点击。

问题 6：仪表盘学生数量统计源错误

现象

学生端作业提交成功后，仪表盘上显示的学生数量为 0，因为统计仍只查 sys_user 表（教师管理系统用户）。

分析

解决

问题 7：注册页面残留学生选项

现象

注册页面仍显示「学生」和「老师」身份选择器，但系统已改为仅老师注册使用。

解决

删除 RegisterView.vue 中的身份选择器组件、相关 TS 类型、样式代码，后端 UserRegisterDTO 的 status 字段默认设为 2（老师身份）。

总结

今天的改动核心是把作业提交改为游客模式，过程中暴露了几个典型的全栈坑：

层面 问题 根因类型
认证 自定义过滤器未放行 两层认证的放行遗漏
数据 JSON 提取不完整 字符串处理不够健壮
数据库 旧表约束不兼容新逻辑 表设计未考虑 Schema 变化
前端 重复请求 按钮缺少 loading 状态
统计 计数值来源错误 业务逻辑未随数据源变化更新

教训：需求改动时要通盘考虑认证、数据处理、数据库约束、前端交互四个层面，缺一不可。
